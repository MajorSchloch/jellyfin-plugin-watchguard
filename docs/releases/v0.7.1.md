# WatchGuard v0.7.1 — Activity browser usability

The activity browser keeps search, owner, status and sorting close at hand, with compact date controls and less space above the first cards on phones. Concise result counts and loading states distinguish preliminary watchlists, background population, paused preparation, updates and recovery. Coverage and search scope remain available in an expandable explanation.

User rows show readable names and explicitly labelled Added and Last played dates. Expand dates for exact localized timestamps, or expand additional people without a scrollbar inside the card. Episode extras remain accessible by keyboard and touch; future and uncertain episodes stay separate from aired progress. Unchanged rows, open details and posters survive updates and pagination.

The v0.7.0 server query and authorization behavior is preserved: global filtering/sorting, four-request preparation, manual result pagination, visible-page polling every 30 seconds, and authorized checks for deeper views. Known activity is not exhaustive library coverage. Deeper views retain their order; playback labels indicate when state may be stale. Snapshot expiry still requires refresh with the same filters.

Deletion enforcement, approvals, authoritative Protection, personal formats, plugin identity and Jellyfin ABI are unchanged. Requires Jellyfin Server/Web 12.2.0 and .NET 10.

See the [query contract](https://github.com/MajorSchloch/jellyfin-plugin-watchguard/blob/master/docs/activity-browser-v070.md) and [v0.7.1 qualification and screenshots](https://github.com/MajorSchloch/jellyfin-plugin-watchguard/blob/master/docs/activity-browser-validation-v071.md).
