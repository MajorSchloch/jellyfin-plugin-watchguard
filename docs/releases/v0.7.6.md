# WatchGuard v0.7.6 — explicit compatibility capabilities

WatchGuard now reports runtime/API, native deletion interception and browser integration independently. Integration status separates configured enforcement from verified active server protection and shows actionable failures.

Qualified Server/Web releases remain 12.2.0 and 12.3.0. Patch releases in those two families may be accepted only when the mandatory capability checks pass, with a visible “compatible but untested” status. New minor/major versions remain unsupported. Required native routes, authorization, binding and final guard attachment are verified; a version or signature match alone cannot establish protection.

The .NET 10 target, Jellyfin 12.2 dependencies and minimum catalog ABI 12.2.0.0 are unchanged. Incomplete interception retains the existing failure behavior: unrecognized routes can remain unguarded, while attached enabled guards reject unsafe operations. There is no server-wide blocking mechanism.

See the [compatibility policy](https://github.com/MajorSchloch/jellyfin-plugin-watchguard/blob/master/docs/compatibility-capabilities.md), [qualification evidence](https://github.com/MajorSchloch/jellyfin-plugin-watchguard/blob/master/docs/qualification-v076.md) and [installation guide](https://github.com/MajorSchloch/jellyfin-plugin-watchguard/blob/master/README.md).
